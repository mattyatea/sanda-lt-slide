具体的な動画では、どう進んでいるか

本人管理の字幕リポジトリと公式記事を照合して、説明の働きを分解しました。時刻は公開字幕の位置です。以下の「働き」は構成上の観察であり、本人が命名した共通テンプレートではありません。

① The essence of calculus

1:26 円の面積 → 2:05 同心円の輪に分割 → 2:46 輪を伸ばす → 6:15 三角形の面積 → 15:20 微積分の基本定理

「円の面積は分かる。
でも、なぜその式になる？」から始め、同じ円を輪に分けて、扱いやすい形へ移していきます。
輪を長方形とみなす近似を、薄くするとどうなるかで確かめ、最後に一般的な関係へ進みます。

観察 — 完成した別の図へ切り替えるだけでなく、さっきの物がどう変わったかを追えることが納得を支える。
LTへの応用 — 投稿者・本文・投稿時刻を保ち、「同じ投稿」の表示が別のタイムラインに増える瞬間を見せる。

② But what is a Neural Network?

0:04 手書きの3 → 0:49 プログラムにすると？ → 4:03 中間の層はまだ謎 → 6:57 小さな線へ分解

人ならすぐ読める数字を入口に、同じ作業を機械へ説明しようとすると難しくなる、と視点を変えます。入力と出力を先に見せ、中間を未解決の問いとして残します。線や輪を組み合わせる考えが、層を導入する動機になります。

観察 — 「簡単に見えることの中に疑問を発見する」型。
LTへの応用 — 「フォローして読む」は既知の行為として保ち、「二人の登録先が違ったら？」だけを変える。
この動画の線・輪の説明も、実際の学習結果を保証する説明ではなく、構造を理解するための期待として扱われている。

③ Solving Wordle using information theory

3:29 WEARYはよい初手？ → 3:39 比較する点数が欲しい → 7:27 得られる情報を平均する → 12:04 エントロピーの命名の話

具体的な候補語を比べるうちに、文字の印象だけでは初手の良さを決められなくなります。色のパターンが残す候補数を見て、得られる情報量を測る必要が生まれます。その後も、単語の出やすさを考慮するなど、モデルを改善します。

観察 — 用語のエントロピー自体は冒頭ですでに予告される。
したがって「名前は絶対に最後」が共通法則ではない。
大切なのは、その意味を必要とする具体的な問題が育つこと。

LTへの応用 — タイトルに「分散型SNS」があってもよい。
最初からその定義を理解させようとしない。

補足 — Bitcoinは「問題を直すたびに、次の仕組みが必要になる」

公式記事では、友人同士の共有台帳から始め、勝手に記入できる問題から署名へ、署名済み取引をコピーできる問題から取引の識別へ進みます。必要な部品を一覧で教えるのではなく、素朴な仕組みの困りごとを一つずつ解いています。

今回も「別の場所にいる」「それでも読みたい」「返信もしたい」という順なら、次の図が出る理由を聞き手と共有できます。これは公式記事版からの補足分析であり、動画本編の各カットや時刻まで確認した分析ではありません。

動画の作り方として、何を取り入れるか

2023年のDwarkeshとの対談で本人は、アニメーションをタイムラインに配置し、音声を録音して編集すると説明しています。細かなカットや図を作る行為自体が、何をどう伝えるか考える工程になっているとも述べています。これは当時の制作方法の説明であり、現在の全制作体制を断定するものではありません。

対談の「How Grant makes videos」1:05:12〜

今回の制作への提案
  1. まず「最後にどんな見方が変わってほしいか」を一文で決める。
  2. その直前に、聞き手が持っている自然な予想を置く。
  3. 同じ人物・投稿・画面を使い、変える条件を一つに絞る。
  4. 紙芝居の静止状態で、話がつながるか確かめる。
  5. 投稿の到着など、因果関係が見える箇所に動きを付ける。
  6. ページを送りながら口頭で試し、「なぜ次が出るのか」が弱い所を直す。

この手順は本LTへの提案です。Manimへの移行は必要ありません。Marpの段階表示と既存の動く図で、同じ目的を実現できます。まっちゃてぃーさんの短い言葉と即興の話し方は残します。

いまのスライドに足りない一段

問いは「別のSNSの投稿を見られるか」だけでは不十分です。公開ページを開いたり、スクリーンショットや転載を見たりすることとは区別して、「相手側に登録せず、自分のタイムラインへ継続して届くか」に絞ります。

現行の流れ聞き手に起こること次の設計で変えること
別々のSNSを紹介し、すぐにフォローできると教わるが、どこが新しいか比較できない「相手を見るために同じSNSへ行く？」という選択を先に置く
投稿が届くと見出しで予告結果が分かった状態で図を見る到着前は「どこに届く？」、到着後に意味を言葉にする
一対一から突然Cさんも現れる人物と前提を追い直すまずA・Bだけで一度納得。Cは「もう一人なら？」の次の実験として追加
国・県・市の分類を説明覚える新語が一度に増えるつながる理由への答えとして出す。分類だけで発見の代わりにしない

冒頭の絵コンテ案 — 予想から気づきへ

「普通のSNSは全部閉じている」と断定せず、聞き手が普段している使い方から始めます。実在のTwitterとInstagramのロゴを接続する図は使いません。途中で「ここからは、つながれるSNSの例」と口頭で場面を切り替え、同じAさんとBさんで比較します。

驚かせて終わらせない

最初の投稿は意外な出来事として見せ、次の返信は聞き手が予想できる出来事として見せます。この「次は分かる」が、単なる驚きから理解へ進んだ手がかりになります。

20分全体をどう配分するか

時間章ここで分かること
0–7分普段の体験・予想・投稿の到着別々の場所のまま交流できる
7–10分どうやって？ Misskeyと、国・県・市登録先は複数あり、共通のルールでつながる
10–11分水分補給の休憩自分なら何を話すか、考える余白
11–15分好きな話、Twemojiの反応、場所の雰囲気自分が楽しむ場面を想像できる
15–18分どこを選ぶ？ どう始める？紹介やルールを見て、まずのぞく
18–19分もう一つの場所を持つ今のSNSと一緒に試してよい
19–20分案内・締め・進行の余裕次に開く公式ガイドが分かる

国・県・市は残せますが、一対一の投稿を理解した後に置きます。最初は「この二つのSNSがやり取りできるのは、共通のルールがあるから」で十分です。比喩は、その後に複数の登録先やMisskey・Mastodonの関係を整理する役を持たせます。

動きを増やすより、動く理由を揃える

場面動かすもの固定するもの
最初の予想ページ送りで条件だけ変更A・Bの位置、名前、投稿内容
投稿の到着一つの投稿の表示が別画面へ増える送り手の元投稿、受け手の登録先
返信逆方向の会話二つのSNSの枠
複数SNS意味を理解したあとに連続して流す人物と場所の対応
リアクションTwemojiが不規則に増える投稿本文と画面全体

見せ場の決定的な一回は、話すタイミングに合わせて送ります。常時動く図やランダムなリアクションは、仕組みを理解したあとの「実際にはこんなに行き交う」という楽しさに使います。停止ボタンを追加する必要はありません。
